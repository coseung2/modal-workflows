# 스틸컷으로 카메라와 동작 설계하기

사용자에게 카메라 용어만 나열하지 말고 **카메라가 실제로 보게 될 화면**을 스틸컷으로 보여준다. 최종 영상과 같은 화면 비율로 만들고, 컷별 화면을 나란히 배치해 연결을 검토한다. 무드보드는 같은 장면의 스타일 6가지이고, 스토리보드는 선택된 스타일의 시간 순서·카메라·행동 설계다.

## 컷당 필요한 화면

| 상황 | 기본 표현 |
| --- | --- |
| 고정 카메라·단순 행동 | 대표 스틸컷 1장 |
| 카메라 이동·프레이밍 변화 | 시작·끝 2장과 이동 방향 표시 |
| 접촉·들기·마시기 등 복잡한 행동 | 시작·중간·끝 3장. 카메라가 고정이어도 행동에 필요하면 사용 |

복잡한 컷은 3장 안에 카메라 변화와 행동을 함께 표현한다. 카메라 2장과 행동 3장을 기계적으로 더해 5장을 만들지 않는다. 컷마다 왜 추가 화면이 필요한지 판단한다.

각 컷 아래에는 **컷 번호·최종 사용 길이·숏 크기·카메라 높이/각도·움직임·인물 행동**을 짧게 쓴다. 예: “B · 4초 · 손/컵 클로즈업 · 약간 높은 3/4 · 컵을 따라 위로 이동 · 오른손으로 잡아 가슴 높이까지 듦”.

## 검토용 보드 만들기

1. 선택된 무드보드·캐릭터·제품과 실제 음성 길이를 기준으로 컷의 시작·끝을 설계한다.
2. 기존 이미지나 간단한 로컬 스케치로 구도 초안을 만들 수 있다. 이미지 생성으로 시안을 만들면 **스토리보드 검토용 호출**이라고 표시하고 기존 승인 범위에 포함되는지 확인한다. 새 이미지 생성은 무료로 가정하지 않는다.
3. 컷마다 한 행을 사용하고 시작→중간→끝 순서로 배치한다. 한 장인 컷은 억지로 복제하지 않는다. 컷 경계와 화면 내부 시간 흐름을 구분한다.
4. 번호·시간·설명·화살표는 로컬에서 정확하게 합성한다. 실선은 카메라 이동, 점선은 인물·물체 동작처럼 범례를 정한다. 앞뒤 이동은 시작·끝 화면의 피사체 크기 차이와 “접근/후퇴” 설명으로 표현한다. 애매한 화살표만으로 처리하지 않는다.
5. 인물의 시선·잡는 손·컵 높이·동작 방향·카메라 축을 인접 컷과 대조한다. 카메라가 보는 화면만으로 위치 관계가 모호할 때만 간단한 위에서 본 배치도를 보조로 붙인다.
6. 보드를 실제로 보여주고 연출·편집안과 함께 승인받는다. 명시적 위임·기존 승인은 존중한다. 검토용 시안과 승인 후 실제 생성용 입력은 구분한다.

## 검토본과 H3 입력 구분

- **검토용 보드:** 격자, 컷 번호, 화살표, 설명, 시작·끝 화면을 포함해도 된다.
- **H3 입력:** 한 장면의 깨끗한 개별 원본이다. 격자·번호·화살표·자막이 포함된 검토본을 보내지 않는다. 원본과 표시를 얹은 사본을 구분해 보존한다.
- 선택된 검토 스틸이 충분한 품질의 깨끗한 시작 프레임이면 검수 후 재사용한다. 낮은 해상도의 그리드 캡처를 자동으로 확대해 입력하지 않는다. 필요한 추가 생성은 호출 수에 포함한다.
- 현재 `mode: image`는 첫 프레임 입력이다. 보드의 끝 스틸은 동작·카메라 목표를 설명하는 자료이며 자동으로 마지막 프레임에 고정되는 기능이 아니다. 시작·중간·끝 그림이 있다고 실제 영상이 그 움직임을 정확히 따랐다고 주장하지 않는다.
- 스토리보드 시안 생성은 승인 전 검토를 위한 단계다. **보드 승인 전 본 생성용 장면 확정·H3 영상 제출을 진행하지 않는다.** 전체 제작 진행 허락과 보드 선택·승인을 구분한다.

## 제출 전·생성 후 검사

보드에서는 얼굴·의상·컵 형태와 손, 시점, 화면 크기 변화, 카피 여백, 컷 간 연속성을 확인한다. 생성 후에는 실제 클립의 시작·중간·끝 프레임을 보드와 비교한다. 정지 스틸의 줌·패닝을 실제 인물 동작 생성으로 대신하지 않는다. 다른 결과가 나왔다면 편집 가능한 구간 선택 또는 수정 방향을 보고한다.

이 문서는 시각화 방법의 지침이다. 보드 자동 렌더러나 마지막 프레임 제어 기능을 제공하는 것은 아니다. 결과는 저장소 밖 작업 폴더에 보관한다.

# 생성 전에 정하는 연출과 컷 편집

에이전트는 사용자가 원하는 결과에 맞춰 **편집을 먼저 설계하고 그 편집에 필요한 클립을 생성**한다. 아래는 의사결정 가이드이며 효과 목록을 모두 사용하는 체크리스트가 아니다. 별도 제작 관리 시스템이나 특정 편집기 설치를 요구하지 않는다.

## 연출안에 포함할 결정

| 요소 | 구체적으로 정할 것 |
| --- | --- |
| 광고 목적 | 누구에게 무엇을 기억시키고 어떤 감정을 남길지. 한 문장으로 정의 |
| 후킹 | 첫 1–2초에 볼 이유를 만드는 동작·질문·화면·소리. 제품과 관계없는 자극은 피함 |
| 변화·반전 | 처음과 끝의 상태 변화, 전환 시점과 계기. 억지 반전 대신 발견·감정 변화도 가능 |
| 브랜드 | 제품 경험과 브랜드 약속의 연결, 이름을 언제 어디에 얼마나 오래 보여줄지 |
| 숏·시점 | 와이드/미디엄/클로즈업, 눈높이/하이/로우, 정면/3/4/측면, 관찰 시점/인물 시점 |
| 카메라 | 고정·팬·틸트·돌리·트래킹 중 목적에 맞는 움직임, 방향·속도·시작/종료 구도 |
| 컷 연결 | 컷을 바꿀 정확한 행동 시점, 시선·동작 방향·손·물체 위치·화면 축 유지 |
| 트랜지션 | 하드 컷, 동작 연결, 소리가 먼저/나중에 이어지는 연결, 디졸브 등의 선택 이유 |
| 리듬 | 빠른 구간과 머무는 구간, 호흡·제품 인지·카피 읽기에 필요한 시간 |
| 음향 | 내레이션·음악·환경음·효과음의 우선순위, 침묵, 시작/끝과 전환 시점 |
| 타이포 | 실제 폰트 파일·사용 조건·굵기·크기·행간·색·안전 여백·등장/퇴장·읽기 시간 |

반전·음악·빠른 컷을 모든 작업에 강제하지 않는다. 브랜드와 목적에 맞는 안을 제안한다. 단순 클립 요청에는 불필요한 광고 설계 단계를 추가하지 않는다.

## 승인받을 편집 설계표

[스틸컷 스토리보드 지침](visual-storyboard.md)에 따라 실제 카메라 화면을 시각화한다. 고정은 대표 1장, 이동은 시작·끝 2장, 복잡한 행동은 3장으로 표현한다. 검토용 보드에는 번호·방향 표시를 넣되 H3에는 표시 없는 개별 원본만 사용한다. 승인 전 검토용 시안 생성과 승인 후 본 영상 생성을 구분한다.

스토리보드에는 컷 번호, 최종 타임라인의 입점·출점, 컷의 역할, 시작→행동→종료, 숏·시점·카메라, 앞뒤 연결, 음성·효과음·카피, 필요한 생성 입력을 함께 표시한다. “시네마틱하게”, “적절한 전환” 같은 말만으로 남기지 않는다. [온유 연출안](../examples/onyu-direction.md)을 구체적인 작성 예로 사용한다.

실제 TTS 길이를 측정하고 편집 구간을 조정한 뒤 사용자에게 보여준다. 기존 스토리보드 승인 단계에 연출·편집 결정을 포함해 한 번에 검토하게 한다. 이미 받은 승인이나 명시적 위임은 반복 확인하지 않는다. 검토용 스틸 시안은 승인된 범위에서 먼저 준비하되, 보드 승인 전 본 생성용 장면 확정·H3 영상 제출은 진행하지 않는다.

## 생성용 숏으로 변환

- 한 생성 클립에 한 가지 주된 동작을 넣고 시작·끝 상태를 분명히 쓴다. 여러 컷을 한 프롬프트에 섞어 모델에 편집을 맡기지 않는다.
- 최종 편집 길이와 생성 요청 길이를 구분한다. 클립 앞뒤에 편집 여유를 확보하되 H3 최대 15초와 프레임 단위 길이 조정을 고려한다.
- 같은 배우·의상·제품·배경·광원·손·시선·동작 축을 연결한다. 앞 컷 마지막 상태와 다음 컷 첫 상태가 다르면 동작 연결을 강행하지 않는다.
- 생성 후 실제 사용 가능한 구간을 고른다. 정지 이미지에 줌을 넣은 것을 인물 행동 생성으로 대체하지 않는다.
- 인물 정체성·손·제품 형태가 바뀌면 전환 효과로 숨기지 않는다. 승인 범위 안의 재생성이나 컷 구성 수정을 제안한다.

## 로컬 편집 실행

먼저 FFmpeg/ffprobe 또는 사용자가 선택한 도구의 실행 가능 여부, 자막·폰트·오디오 기능을 확인한다. 부족하면 목적·설치 방법·비용을 설명한다. 영상들을 단순 파일 순서로 연결하지 말고 승인된 타임라인의 사용 구간을 트림해 배치한다.

기본은 명확한 하드 컷이다. 행동 중 컷 전환은 속도·방향·접촉 상태를 맞춘다. 같은 행동을 앞뒤 컷에서 반복하지 않는다. 디졸브는 시간·정서 전환이 필요할 때만 사용하며 얼굴·손이 겹쳐 보이지 않는지 확인한다. 시각 효과보다 소리의 선행·잔향·감쇠로 자연스럽게 연결할 수도 있다.

클립 간 해상도·프레임레이트·색·음량을 맞춘다. 원본 생성 오디오를 쓸지 음소거할지 컷별로 정한다. TTS를 우선 들리게 하고 음악은 음성 아래로 낮춘다. 정확한 문구·브랜드 표기는 로컬에서 합성한다. 다른 폰트로 조용히 대체하지 말고 누락을 확인해 대체안을 알린다.

## 완료 판정

- 첫 화면만 보아도 시선의 중심과 볼 이유가 있는가?
- 무음으로 보아도 행동과 감정 변화가 이해되는가? 음성만 들어도 문장이 자연스러운가?
- 시선·잡는 손·컵 위치·의상·광원과 행동의 시작/끝이 이어지는가?
- 전환이 내용을 돕는가? 같은 동작이 반복되거나 의도치 않은 점프가 없는가?
- 제품과 브랜드를 기억할 시간이 있으며 작은 화면에서 문구가 읽히는가?
- 한글·영문 표기, 자막 타이밍, 폰트 누락, 음성 겹침·클리핑, 마지막 프레임을 확인했는가?
- 최종 파일 전체 디코드와 실제 시청 검수를 구분해 보고했는가?

이 문서는 에이전트가 따르는 연출 절차다. CLI가 자동으로 광고를 편집하거나 품질을 판정하는 기능이 내장된 것은 아니다.
